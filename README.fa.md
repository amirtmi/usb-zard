# usb zard — راهنمای فارسی

[صفحه اصلی](README.md) · [English](README.en.md)

## معرفی برنامه

usb zard یک برنامه دسکتاپ برای Windows 10/11 x64 است که با C#، .NET 8 و WPF ساخته شده است. هدف آن بررسی مشکلات محافظت نوشتن در فلش USB و کارت SD/microSD و اجرای روش‌های استاندارد و کنترل‌شده ویندوز است.

برنامه تلاش می‌کند میان ویژگی فقط‌خواندنی ویندوز، فایل‌سیستم RAW یا ناشناخته، خطای دستگاه و اطلاعات ناموجود تفاوت بگذارد. پیام «فرمان اجرا شد» به‌تنهایی به معنی تعمیر دستگاه نیست.

**هیچ نرم‌افزاری نمی‌تواند تمام قفل‌های سخت‌افزاری، firmware یا خرابی NAND را روی همه فلش‌ها و کارت‌ها رفع کند.**

## پیش‌نیاز و اجرا

- ویندوز ۱۰ یا ۱۱ نسخه x64.
- دسترسی مدیر از طریق پنجره UAC.
- Windows PowerShell 5.1 و اجزای Storage/WMI ویندوز.
- برای ساخت از سورس، SDK نسخه .NET 8 لازم است.
- نسخه مستقل Release به نصب جداگانه .NET Runtime نیاز ندارد.
- برنامه نصب‌کننده و وابستگی NuGet شخص ثالث ندارد.
- فایل اجرایی امضای تجاری ندارد؛ آن را از Releases همین مخزن دریافت و هش SHA-256 را بررسی کنید.

ZIP را استخراج و **usb zard.exe** را اجرا کنید. برنامه در حال اجرا را روی فلشی که می‌خواهید فرمت کنید قرار ندهید.

## روش پیشنهادی استفاده

۱. پیش از تغییر، فایل‌های قابل‌خواندن و مهم را در محل دیگری پشتیبان بگیرید.

۲. «جستجوی دستگاه‌ها» را بزنید. مدل، ظرفیت اعلام‌شده و سریال را بررسی و دستگاه درست را انتخاب کنید.

۳. «تشخیص» را اجرا کنید. این مرحله اطلاعات را می‌خواند و روی رسانه نمی‌نویسد.

۴. برای عملیات مرتبط با فایل‌سیستم، پارتیشن هدف را نیز صریحاً انتخاب کنید.

۵. یافته‌ها، کد خطا و اقدام بعدی را بخوانید و تنها عملیات متناسب با وضعیت را انتخاب کنید.

۶. برای عملیات تغییردهنده، هشدار را بخوانید و عبارت تأیید را دقیقاً تایپ کنید.

۷. تا پایان عملیات دستگاه را جدا نکنید و برنامه را نبندید.

۸. پیش از خروج، گزارش TXT یا JSON را ذخیره کنید.

**RAW با Write Protected یکسان نیست.** RAW یعنی ویندوز فایل‌سیستم قابل‌استفاده را تشخیص نمی‌دهد. برداشتن ویژگی فقط‌خواندنی، ساختار فایل‌سیستم را بازسازی نمی‌کند. CHKDSK و آزمون فایل برای RAW مسدود هستند. اگر داده مهم دارید ابتدا بازیابی را در نظر بگیرید؛ فرمت فقط با پذیرش پاک‌شدن داده‌ها انجام شود.

## اطلاعاتی که برنامه بررسی می‌کند

مدل و هویت دستگاه، سریال، نوع اتصال، ظرفیت اعلام‌شده، شناسه پارتیشن/Volume و فایل‌سیستم خوانده می‌شوند. اطلاعات PnP و VID/PID در صورت ارائه توسط ویندوز ثبت می‌شوند.

ویژگی فقط‌خواندنی دیسک، ویژگی پارتیشن و پاسخ دستگاه/درایور به پرس‌وجوی قابلیت نوشتن سه موضوع جدا هستند. اگر ویژگی پارتیشن پشتیبانی نشود، مقدار آن «نامشخص» باقی می‌ماند؛ نامشخص را خاموش فرض نمی‌کنیم.

پرس‌وجوی بومی **IOCTL_DISK_IS_WRITABLE** بدون نوشتن داده انجام می‌شود. همچنین نمونه محدودی از ابتدای رسانه خوانده می‌شود تا مواردی مانند تماماً صفر بودن نمونه یا نبود امضای بوت گزارش شود. این بررسی، اسکن کامل سطح، بازیابی داده یا اثبات خالی‌بودن کل حافظه نیست.

شمارنده‌های سلامت فقط در صورت تطبیق معتبر هویت دیسک نمایش داده می‌شوند. نبود SMART یا عنوان «Healthy» ویندوز، سالم‌بودن حافظه فلش را ثابت نمی‌کند.

## عملیات موجود

| گزینه | عملکرد و دامنه اثر |
|---|---|
| تشخیص | جمع‌آوری شواهد فقط‌خواندنی و تولید یافته‌های دو‌زبانه |
| رفع فقط‌خواندنی دیسک | استفاده از Set-Disk؛ اگر ویژگی از قبل خاموش باشد، «بدون تغییر» گزارش می‌شود |
| رفع قفل پارتیشن | اجرای DiskPart در حالت اسکریپت و بررسی ویژگی فقط‌خواندنی فایل‌سیستم؛ در MBR ممکن است بر تمام پارتیشن‌های همان دیسک اثر کند |
| بازخوانی اتصال | تازه‌کردن کش ذخیره‌سازی؛ اتصال مجدد با خروج امن و وصل‌کردن دستی انجام می‌شود |
| اصلاح سیاست ویندوز | پشتیبان‌گیری و تغییر WriteProtect محلی؛ این تنظیم سراسری رایانه است و سیاست سازمانی دور زده نمی‌شود |
| بررسی فایل‌سیستم | اجرای CHKDSK بدون تعمیر برای فایل‌سیستم شناخته‌شده و پشتیبانی‌شده |
| تعمیر CHKDSK | تعمیر با تأیید مستقل؛ ممکن است ساختار فایل‌سیستم یا اطلاعات آسیب‌دیده را تغییر دهد |
| آزمون نوشتن و خواندن | ساخت فایل تصادفی ۱ MiB، تخلیه، بازخوانی، مقایسه SHA-256 و حذف فقط همان فایل موقت |
| فرمت و پاک‌کردن | فرمت سریع اختیاری exFAT، NTFS یا FAT32 و سپس بررسی نتیجه |

CHKDSK با اجبار به جداسازی Volume، بازیابی سکتور خراب یا زمان‌بندی هنگام بوت اجرا نمی‌شود.

فرمت FAT32 برای پارتیشن بیش از ۳۲ GiB به‌صورت محافظه‌کارانه رد می‌شود. برنامه ابتدا Format-Volume را اجرا می‌کند و در صورت خطا می‌تواند از DiskPart /s استفاده کند. حالت اسکریپت در اولین خطا متوقف می‌شود.

برای تأیید فرمت، باید عملیات فرمت پذیرفته شده باشد، فایل‌سیستم خواسته‌شده با اندازه غیرصفر ظاهر شود و آزمون کوچک نوشتن/بازخوانی موفق باشد. کد خروج فرایند به‌تنهایی نشان‌دهنده تعمیر نیست.

آزمون ۱ MiB کل ظرفیت، واقعی‌بودن ظرفیت یا ماندگاری پس از قطع برق و اتصال مجدد را اثبات نمی‌کند. اگر حذف فایل موقت شکست بخورد، مسیر فایل و خطای حذف در گزارش ثبت می‌شوند.

## محافظت از داده

- هنگام شروع برنامه هیچ تعمیر خودکاری اجرا نمی‌شود.
- تغییرات به تایپ عبارت تأیید نیاز دارند؛ فرمت عبارت مستقل برای پذیرش پاک‌شدن دارد.
- مسیر، هویت، سریال، ظرفیت، نوع اتصال و ویژگی‌های بوت/سیستم دوباره بررسی می‌شوند.
- ارتباط پارتیشن و Volume و شناسه آن‌ها نیز کنترل می‌شود.
- دستگاه داخلی، سیستمی، بوت و هویت نامطمئن برای تغییر پذیرفته نمی‌شوند.
- عملیات Volume تنها برای حرف درایو غیرسیستمی D تا Z و انتخاب صریح کاربر انجام می‌شود.
- برنامه فرمانی برای clean، پارتیشن‌بندی مجدد، نوشتن خام سکتور، فلش‌کردن firmware یا ابزار تولید کارخانه ندارد.
- عملیات ذخیره‌سازی در حال اجرا به زور متوقف نمی‌شود.

شماره دیسک یا حرف درایو به‌تنهایی هویت کافی نیست. این کنترل‌ها همه خطرهای تعویض هم‌زمان دستگاه را به‌شکل اتمی حذف نمی‌کنند؛ هنگام عملیات، اتصال را تغییر ندهید.

## گزارش و عیب‌یابی

گزارش شامل زمان، هدف، عمل انجام‌شده، توضیح فارسی/انگلیسی، یافته‌ها، توصیه بعدی، کد خطا و جزئیات ساختاریافته است. TXT برای خواندن و JSON برای بررسی فنی مناسب است. سابقه نشست تا هنگام ذخیره در حافظه برنامه نگه داشته می‌شود.

گزارش می‌تواند شامل سریال، شناسه Volume، مسیر دستگاه و جزئیات سیاست ویندوز باشد. پیش از انتشار در Issue آن را بررسی یا ویرایش کنید.

- **NO_CHANGE:** ویژگی فقط‌خواندنی دیسک از قبل خاموش بوده؛ تعمیر رسانه ادعا نمی‌شود.
- **RAW_FILESYSTEM:** فایل‌سیستم قابل‌شناسایی نیست؛ CHKDSK و آزمون فایل اجرا نمی‌شوند.
- **CHKDSK_4:** WMI پیام «رسانه در درایو یافت نشد» داده است؛ این به‌تنهایی خرابی NAND را ثابت نمی‌کند.
- **FORMAT_NOT_VERIFIED:** فایل‌سیستم قابل‌استفاده موردنظر تأیید نشده؛ خطاهای روش اصلی و جایگزین حفظ می‌شوند.
- **WRITE_VERIFY_FAILED:** نوشتن/بازخوانی فایل تأیید نشده است.
- **GUARD_…:** بررسی ایمنی عملیات را متوقف کرده؛ دستگاه را دوباره جستجو و تطبیق دهید.

اگر چند روش استاندارد شکست خوردند، پاک‌سازی را بی‌هدف تکرار نکنید. پورت مستقیم دیگر، کارت‌خوان دیگر در صورت کاربرد، و رایانه دیگری را امتحان کنید. در صورت تداوم مشکل، برای داده ضروری بازیابی تخصصی و برای استفاده مجدد تعویض دستگاه را در نظر بگیرید.

## ساخت و آزمون

از ریشه مخزن در ویندوز اجرا کنید:

```powershell
dotnet build UsbWriteGuard.csproj -c Release
dotnet run --project Tests/UsbWriteGuard.Tests.csproj -c Release
powershell -NoProfile -ExecutionPolicy RemoteSigned -File Tests/Guard.Tests.ps1
powershell -NoProfile -ExecutionPolicy RemoteSigned -File Tests/Worker.Tests.ps1
dotnet run --project Tests.Ui/UiSmoke.csproj -c Release -- previews
dotnet publish UsbWriteGuard.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -p:DebugSymbols=false -o release
```

RemoteSigned در فرمان‌های بالا فقط مربوط به فرایند آزمون است و سیاست کل سیستم را تغییر نمی‌دهد. سیاست مدیریت‌شده سازمانی را دور نزنید. آزمون‌های ارائه‌شده از اطلاعات مصنوعی یا فرمان‌های ذخیره‌سازی شبیه‌سازی‌شده استفاده می‌کنند و فلش متصل را فرمت نمی‌کنند.

## ساختار پروژه

- MainWindow.xaml و MainWindow.xaml.cs: رابط، فعال/غیرفعال‌کردن عملیات، تأیید و خروجی گزارش.
- Models.cs: اطلاعات دستگاه، پارتیشن، یافته و عمل.
- Services/Backend.cs: اسکریپت‌های داخلی معتبر و تبادل UTF-8/JSON.
- Services/Diagnosis.cs: تولید یافته‌ها بر پایه شواهد.
- Services/ResultText.cs: توضیح دو‌زبانه نتیجه و خطا.
- Backend/Guard.ps1: کنترل هویت، پارتیشن و تأیید.
- Backend/Native.ps1: پرس‌وجوی بومی، اجرای DiskPart و آزمون فایل.
- Backend/Worker.ps1: عملیات استاندارد ویندوز.
- Assets: لوگو و آیکن.
- Tests و Tests.Ui: آزمون‌های مصنوعی، شبیه‌سازی و رندر رابط.

همه کنترلرها، کارت‌خوان‌ها، وضعیت‌های رمزگذاری و ساختارهای ذخیره‌سازی پشتیبانی نمی‌شوند. فهرست منابع رسمی Microsoft در [راهنمای انگلیسی](README.en.md#microsoft-api-references) آمده است.
